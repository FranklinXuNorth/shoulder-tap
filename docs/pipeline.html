shoulder-tap 数据处理

每个字段是谁写的、住在哪、什么时候会对不上。 配套读 数据流 和 渲染流程。

Q：Vercel 和 Notion 的 ID 怎么对齐？用户改了会不会出问题？
不用对齐 —— Vercel 上没有任何副本可言。

那台服务器不存 ID、不存映射、不存上次时间。due_check 是个纯函数： 你给它哪些 ID，它就在哪些 ID 里挑出到点的还给你。它记不住上一次你给过什么， 所以也就谈不上「不同步」。真正会出问题的地方全在 Notion 内部，见第 04 节。

01 — 所有权

每个字段归谁管

一张表看完。凡是「你」那一列，你随手改都不会弄坏什么 —— 那本来就是你的数据。

字段谁写谁读你手改安全吗
Name模型（照你的原话）模型随便改
Kind模型，建行时定模型筛选用别改
ID模型，建行时签一次模型 ↔ Vercel别改、别留空
Order模型模型排序用改数字可以，拖拽无效
Status模型，且只在你说完成之后模型只能用那三个值
Day模型，建行时写今天模型筛选用改了就挪到那天
EveryMinutes模型，加习惯时Vercel（只看数字）随便改
Last模型，你说做了之后Vercel（只看时间戳）随便改
Note模型模型随便改
Vercel 那一列只出现过两次，而且都只看数字：间隔几分钟、上次是什么时候。 它连这两个数字属于哪条习惯都不知道 —— 它只知道一个叫 h-8b12d4 的东西该做了。

02 — 一次往返

从「我今天要做 A、B、C」到一次拦截

  1. 你说今天要做什么
    local · 模型拆成有顺序的几条
  2. 建行，顺手签 ID
    local → api.notion.com
    Name=把接口文档写完  Kind=task  ID=t-a3f91c
Order=1  Status=pending  Day=2026-09-22
    ID 在这一刻诞生，签之前跟库里已有的比一遍。之后它再也不变。
  3. 下次开口，先读回来
    local ↔ api.notion.com
    按 Order 升序，当前这条 = 第一个 Status ≠ done 的。
  4. 判一档
    local · 模型自己判
    related 放行 / partial 提一句 / unrelated 打手并停住。
  5. 习惯：名字在本地剥掉再送出去
    local → vercel
    送出： [{"id":"h-8b12d4","every_minutes":45,"last":"2026-09-22T01:10:00Z"}]
回来： {"kind":"due","ids":["h-8b12d4"]}
    名字留在本地。回来的 ID 在本地贴回名字。
  6. 写回去，但只在你发话之后
    local → api.notion.com
    你说某条做完了 → Status=done；你说刚做了某个习惯 → Last=现在。 模型自己觉得做完了不算数。

03 — ID

谁签的，凭什么不重复

短 ID 长这样：t-a3f91c / h-8b12d4，前缀区分种类，后面六位十六进制。 建行的那一刻签一次，之后永不变更 —— 改名字不影响它，改间隔不影响它。

问题现在怎么处理
怎么签随机六位十六进制，和当时手上那批已有的比一遍，撞了重签
撞了八次怎么办退回完整 uuid。宁可难看，也不能重复
为什么不用 Notion 的 page id那串 uuid 太长，人看不清、模型也容易抄错
那 page id 还有用吗有 —— 它是天然唯一的兜底身份，短 ID 丢了还能靠它认人
签重的窗口是存在的，只是很窄： 比对的是「当时读到的那一批」，不是全库。两台机器同一秒各建一行，理论上可能撞。 六位十六进制有 1600 万种可能，你一天建十行 —— 这个风险排在「先不管」那一档。

04 — 你手改会怎样

逐种情况，说实话

这一节回答你真正问的那个问题。结论是：大部分改动完全安全，只有三种会真的出问题， 而且都不在 Vercel 那一侧。

你在 Notion 里做的事后果
改 Name（改个说法）安全。ID 没动，一切照常
改 EveryMinutes（30 改 45）安全。下次读就按新的算
改 Last（手动记一笔）安全。这本来就是给你改的
改 Note安全
改 Day（挪到明天）安全。今天就读不到它了，本来也是这个意思
删掉一行安全。Vercel 没有副本要清理
改 Order 的数字安全。顺序就是按这个数排的
拖拽排序没用。Notion 的拖拽不改 Order 数字，模型看不见
Status 填了别的值出问题。只认 pending / done / dropped 三个小写值
手动新增一行出问题。ID 和 Kind 是空的
复制一行（Ctrl+D）出问题。ID 被一起复制，两行同名同号

05 — 三个真的会坏的地方

以及修它们要花多少

空 ID

你在 Notion 里手敲一行习惯，ID 那格是空的。 剥给 due_check 的就是 id: ""，回来的也是 ""， 贴不回任何一条。表现是：那条习惯永远不会提醒你。

修法：读到空 ID 就当场签一个写回去。协议里加三行字的事。

重复 ID

Notion 的复制行会把 ID 一起复制。两行同号之后， due_check 回一个 ID，本地贴回去会命中两条 —— 提醒重复出现，记一笔时也不知道该更新哪行。

修法：读到同号就给后出现的那行重签。同样在协议里。

Status 写歪

Notion 的 select 允许你随手敲一个新选项。写成 Done（大写）之后， Status ≠ done 依然成立 —— 那条任务永远是「当前这条」， 你会被它挡住做别的事。

修法：比对时先小写化。一行代码。
三个都没做，这是故意的。 现在所有的行都是模型建的、模型改的，上面三种情况一次都不会发生。 等真有人开始手改 Notion 了再做也不迟 —— 那时候你还会知道他们到底怎么改， 比现在猜着防要准。

06 — 不变量

哪天觉得不对劲，照这几条查

  • 1每行都有非空 ID，全库不重复
  • 2Kind 只有 task 和 habit，没有第三种、没有空
  • 3同一天的 task，Order 互不相同
  • 4Status 只有 pending / done / dropped，全小写
  • 5habit 行的 EveryMinutes > 0，否则它永远不会提醒
  • 6Vercel 上没有任何状态 —— 这条不用查，它根本没地方存
