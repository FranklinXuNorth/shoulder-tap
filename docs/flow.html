shoulder-tap 流程

从装上，到你一跑偏屏幕右边被拍一下。部件是什么看 architecture。

02 · 每一轮对话

钩子替模型在确定的时刻看一眼，模型没有跳过的余地。桌面那一下也是钩子拍的，不靠模型自觉。

sequenceDiagram
  autonumber
  participant U as 你
  participant CC as Claude Code / Codex
  participant W as watch.mjs
  participant M as mcp.mjs
  participant D as 数据
  participant A as 桌面端

  U->>CC: 说一句话
  CC->>W: UserPromptSubmit
  W-->>CC: 今天的清单 + 判断规则（读缓存）
  W-)D: 后台刷新缓存
  CC->>M: check_focus / set_focus / log_habit …
  M->>D: 读写
  M-->>CC: 结果
  CC->>W: PreToolUse(AskUserQuestion)
  W->>A: 拍拍 + 问题
  CC-->>U: 回答，结尾带拍拍（跑偏了再带 taptap）
  CC->>W: Stop
  W->>A: 结尾有拍拍 → 响指；有 taptap → taptap
  A-->>U: 屏幕右缘：手 + 一句话

03 · 三档判断

拿「你现在要做的」去比今天清单上没做完的每一条。判断是模型自己做的。

flowchart TB
  X["你现在要做的事"] --> J{"是清单上某条没做完的事，
或者完成它必需的一步？"}
  J -->|"是（A）"| G["直接干活，什么都不提"]
  J -->|"完全无关（C）"| C["照做，但回答压到两句话以内"]
  C --> T["结尾：taptap + 一句「第 N 条还没动」"]
  T --> K{"那条完成了 / 重排了 / 今天不做了？"}
  K -->|"没有"| T2["下一轮照提"]
  K -->|"是"| S["不再提"]
  J -.->|"动清单本身的请求"| G

04 · 习惯

一次一行，跟每日任务一样打 pending / done / dropped，历史就是所有不是 pending 的行。到点了不立刻说，等有自然停顿时带一句。

stateDiagram-v2
  [*] --> pending: add_habit
  pending --> pending: 软习惯说不做 · 拒绝，照样提醒
  pending --> done: 你说做了（log_habit）
  pending --> dropped: 硬习惯说今天不做（skip）
  pending --> stopped: 不再盯了（stop_habit）
  done --> [*]
  dropped --> [*]
  stopped --> [*]
  note right of pending
    一个习惯同一时刻只有一行 pending。
    Day = 激活时刻，到没到点从它算。
  end note
  note right of done
    done / dropped 之后自动生成下一行 pending：
    做了从现在算，跳过从明天算。
    stopped 是 dropped 但不生成下一行。
  end note
