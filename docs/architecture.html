shoulder-tap 数据流

模型直接读写你自己的 Notion。Cloudflare 上那台服务只拿得到 ID 和分钟数—— 它不知道你今天要做什么，也不知道你想盯哪个习惯。这页把每一跳、以及每一跳都交出了什么，逐条画出来。

02 — 主回路

你说「帮我改一下落地页配色」之后发生的事

  1. 模型决定先查一下
    Claude Code · 依据 ~/.claude/CLAUDE.md 里那几行
    这一步是规则驱动的，服务端强制不了——所以那几行必须粘进全局 CLAUDE.md。
  2. 取规程
    local → cloudflare · focus_protocol · 请求体是空的
    不带凭据，也没有任何输入。回来的是「该拿什么比什么、三档各自怎么办」。
  3. 读今天
    local ↔ api.notion.com · 中间那台机器不在这条线上
    Kind = task 且 Day = 今天 且 Status ≠ dropped
按 Order 升序 → 当前这条 = 第一个 Status ≠ done 的
  4. 判一档
    Claude Code · 本地，不花服务端一个 token
    「改落地页配色」和「打包厨房的锅碗」语义上毫无关系 → unrelated。
  5. 查到点的习惯
    local → cloudflare · due_check · 名字在本地被剥掉
    送出去： [{"id":"h-8b12d4","every_minutes":45,"last":"…"}]
回来的： {"kind":"due","ids":["h-8b12d4"]}
         h-8b12d4 —— 超了 451 分钟
    ID 对回名字这一步在本地做。服务端自始至终不知道 h-8b12d4 是什么。
  6. 拦下来，然后闭嘴等你回答
    Claude Code
    到点的习惯在回答最后轻轻带一句，不因为它打断正事。

03 — 判断

三档，规则写死在规程里

related 就是当前这条

直接干活，一个字都不要提这次检查。不会替你勾掉——只有你明确说完成了，才去改 Status。

partial 沾边，但不是这条

清单里靠后的某条，或者当前这条的外围。一句话点破：前面那条还没完，这件事算插进来还是先放着？然后照你说的办。

unrelated 压根对不上

照做，不拦你。干完之后在最末尾敲三下，一句话点名今天那条还没动。不问问题、不等回答，但只要那条没完成，每一轮都敲。

它不拦你，只是不肯闭嘴。 拦住不做事的版本试过，那是在跟用户抢方向盘 —— 真锁住你，你下次就不装它了。 现在换成：你要做什么都照做，但每一轮结尾都提醒你那条还没动，直到你完成它、重排它、或者宣布今天不做了。 烦是故意的；提一次就算了的提醒，等于没提醒。

04 — 三条路

同一台服务，三种交出去的程度

默认只有第一条开着。后两条要显式配环境变量才存在。

路径判断在哪做交出去什么开关
零内容（默认）
focus_protocol + due_check		 你本地的模型 ID、分钟数、时间戳 无需配置
Jev 快速判档
classify_focus		 TypeSafe 的 System One 模型 两行文字：现在要做什么 + 当前那条 JEV_API_KEY
服务端代劳 Notion
check_focus 等		 你本地的模型 Notion 密钥 + 全部任务文字 配 Bearer 才可用
第二、三条路都会让内容出你的机器。 第三条是早期版本留下的，配了 Notion 密钥才能用，不配就只是报个错； 第二条只送两行短句，但它确实经过这台 Cloudflare 再到 TypeSafe。 想要「一个字都不出去」，就只用第一条 —— 那也是默认。
