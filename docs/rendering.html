shoulder-tap 渲染流程

判断出结果之后，那一下「拍肩」是怎么落到屏幕上的：谁决定播、播哪九帧、播多久、 怎么收起、以及在不能动画的地方退成什么样。配套读 数据流 和 docs/ASSETS.md。

01 — 管线

从一次判断到一屏敲击

五步，横跨三个地方。注意第三步：名字是在本地才贴回去的，服务端自始至终只见过 ID。

local · 模型 判出一档 related / partial / unrelated
cloudflare due_check 回 {kind:"due", ids:[…]}
local · Notion ID 贴回名字 h-8b12d4 → 你自己起的那个名字
local · 渲染层 拼成事件 {kind, message}
local · overlay 敲三下 1300ms，播一次，不循环 
// 渲染层收到的就是这么点东西，文字全在本地拼
{ "kind": "off-task", "message": "你今天说的第 2 条是「把接口文档写完」，还没动。" }
{ "kind": "due",      "message": "抬头看看窗外 —— 说好每 45 分钟一次。" }

02 — 闸门

四种结果，只有两种会让手伸出来

手从来不打断你正在做的事 —— 它只在回答的最末尾出现。做对了不出现、沾边了不出现， 只有真跑偏和真到点才敲你一下，而且会一直敲到你处理它为止。

related → 不播

你在做对的事。连「检查过了」都不该提，更不用说弹个东西出来邀功。

partial → 不播，只说一句

沾边的事值得提醒一句顺序，但不值得打断。走文字通道，不走动画。

unrelated → off-task

真跑偏了。但不拦你 —— 你要的照做，干完之后在最末尾敲三下 + 一句话。只要那条没做完，每一轮都敲。

到点的习惯 → due

同一只手、同一段动画，只换文字。它不代表你做错了什么。

两类提醒共用一个动作，是故意的。 不按内容画不同的动画 —— 没有喝水杯子、没有走路小人、没有完成礼花。 一个统一的介入信号，你一眼就知道「有人在叫我」，不用先分辨是哪一类。

03 — 帧

九帧，1300 毫秒，三下

下面是真的素材在按真的时长播（tap-glove-sheet.png，864×80，九等分）。 虚线是屏幕边缘。

伸手 → 敲 → 收，三次触边落在第 3、6、8 帧。节奏是「快两下、停一拍、再一下」， 比匀速三下更像真有人在敲你。末帧 300ms 是收手后的留白，让文字有时间被读到。

05 — 收起

它必须很容易被赶走

情况行为
按 Escape立刻收起，动画中断
连续触发先 dismiss 再重播，不堆叠、不排队
动画结束手消失，文字留着 —— 你可能正好没在看
overlay 之外的区域不拦点击、不抢焦点，你该干嘛干嘛
prefers-reduced-motion不播动画，直接显示触边那一帧
读屏文字挂在 aria-live="polite" 上，不打断当前朗读
这一节比动画本身重要。 一个赶不走的提醒，用户只会用卸载来赶它。能被一秒关掉，它才有机会留在你桌面上。
