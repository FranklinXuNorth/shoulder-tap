shoulder-tap 跨机器

一份小 PRD。状态：Worker、发送端、Windows 接收端、登录已实现；Mac 常驻端、MCP 迁移、历史查看未做。Mac 上的 agent 做完了、或者弹了个问题等你回答， 手应该拍在你眼睛所在的那台机器、那块屏上。 现在的数据怎么走，看 数据流。

你在哪台机器前，手就拍在哪台机器上。

现在每一下拍肩都只落在发起它的那台机器上。你同时开着好几台电脑，agent 在 Mac 上跑完了， 而你正盯着 Windows，这一下就白拍了。装好 shoulder-tap、让它在后台常驻，就应该能收到， 不需要 Tailscale，不需要注册账号，也不需要自己开服务器。

01 — 需求

要做到什么

#需求怎么算做到
R1拍拍、taptap、响指三种手势，任何一台机器发起都能跨机器送达在 Mac 上结束一轮，Windows 屏上出现拍拍，字条上写着「[Mac 名] 这轮总结」
R2只拍在当前活跃的那台机器上，而且落在那台机器的活跃屏幕上两台机器都开着，只有你刚刚碰过的那台会出现手
R3只要装了 shoulder-tap 就能用不用 Tailscale、不开端口、不注册；身份沿用你已有的 Notion token
R4服务端读不到内容Worker 和存储里只有频道哈希、随机设备 ID、时间戳和密文
R5延迟在一秒以内走 WebSocket 推送，不靠轮询
R6个人使用零费用落在 Cloudflare Workers 免费档里
R7云端不通时照旧工作连不上就退回现在的行为，在本机拍；钩子永远 exit 0
R8保留拍肩的历史记录每一下拍肩（手势、来源机器、字条）都以密文形式存进频道自己的 SQLite，任何一台机器都能拉下来解密后查看
R9后端统一放在 CloudflareMCP 从 Vercel 迁到同一个 Worker，整个后端只剩一家平台；Claude Code、Codex 等任何支持 MCP 的客户端都能接入
R10收集使用行为数据，不收集内容能统计出每个用户用几台机器、在 Claude Code 和 Codex 之间怎么切换、同时开几块屏；可以一键关闭

02 — 架构

一个 Worker，一个频道对应一个 Durable Object

整个后端都放在一个 Cloudflare Worker 里。/mcp 是从 Vercel 原样迁过来的 MCP， 仍然无状态，拿着用户的 Notion token 读写用户自己的库； /ch/{hash} 是拍肩通道，每个频道一个 Durable Object， 常驻的桌面端用 WebSocket 连上去（开启 hibernation，空闲时不计时长）， 历史记录存在这个 DO 自带的 SQLite 里。

  ───                                  ──────────                          ───────
  Stop / PreToolUse 钩子               Worker  /ch/{hash}                  常驻 shoulder-tap-tap
    watch.mjs                            │                                   │
    ├─ 用 token 派生的密钥加密字条        ▼                                   │
    └─ POST {device, ciphertext} ──▶  Durable Object ── WebSocket 推送 ──▶  解密 → 在活跃屏上播放

  常驻进程 ── 活跃心跳 ─────────────▶  · 只转发给活跃机器

03 — 活跃判定

谁是「你现在在的那台」

在同一台机器里选哪块屏，现在的前台窗口逻辑已经解决了。这一节只管选哪台机器。

只在变化时上报 本机

常驻进程盯着本机上次鼠标点击落在哪块屏、键盘焦点在哪块屏，只有值变了才上报 active。不上报坐标，也不上报窗口标题。

不是当前活跃就立刻上报 补漏

从 Windows 切到 Mac 再切回 Windows 同一块屏，屏幕没变就不会上报。所以 DO 会把「当前活跃设备」广播给所有机器，自己不是活跃的那台，一有键鼠输入就马上上报一次。

时间以服务端为准 时钟

几台机器的时钟对不上，所以用 DO 收到上报的时间排序，不信客户端的时间戳。

通过远程桌面操作 Mac 时，Mac 自己也会收到这些输入，会把自己算成活跃的那台， 手会拍在 Mac 的画面里，你透过远程窗口照样看得到，这正是想要的结果。
没有任何机器在线时，这一下不补拍，只记进历史。拍肩只有当下才有意义，等你十分钟后回来再拍，就只是噪音。

04 — 隐私

上云的只有 UI 上的那一行字，而且是密文

「只上传 UI 文字」本身还不够：taptap 的提醒里有任务名，响指的字条里就是完整的问题。 所以这行字要在发起机器上加密，在收到的机器上解密，服务端全程只经手密文。

东西怎么来服务端能看到
频道HKDF(token, "shoulder-tap/channel")一个哈希，反推不出 token
密钥HKDF(token, "shoulder-tap/key")，AES-GCM看不到，永远不离开本机
设备 ID首次运行时生成的随机 UUID一串随机值；机器名放在密文里
字条、手势、机器名加密成一个 blob只看得到长度
历史记录每条一行：时间戳、设备 ID、密文 blob什么时候、从哪个设备 ID 拍过；内容看不到
活跃心跳设备 ID，外加一个屏幕变了的标记哪个设备什么时候被碰过。这是唯一的明文元数据，路由必须用到它
换 Notion token 等于换频道，所有机器要一起更新 .env，否则彼此收不到。

04a — 账号

身份是账号，密钥仍然只在本机

账号负责两件事：把同一个人的几台机器归到一个频道，以及让行为统计按人算。 字条的加密密钥不从账号来，仍从 Notion token 派生 —— 每台机器本来就有它，不用再同步任何东西， Google 登录也不会碰到「没有密码可派生密钥」的问题。

登录方式 两种

邮箱密码（PBKDF2-SHA256，10 万次，在 Durable Object 里算，绕开 Worker 的 CPU 上限）；Google OAuth（配了 client id 才显示）。没有账号就在第一次登录时建。

设备码 CLI 常见做法

install.mjs 向 Worker 要一个 8 位码和一个只有终端知道的 secret，打印链接；浏览器里登录把码绑到账号；终端拿 secret 轮询换到设备令牌。看见屏幕上的码的人拿不走令牌。

没做 下一步

登录限速、改密码、找回密码、注销设备。现在的账号只够把机器连起来。

04b — 行为数据

只收集元数据，永远不收集内容

用来了解大家实际怎么用：跨机器的需求有多大、在各个 agent 之间怎么切换、开几块屏。 下面每一项都是计数或枚举值，不含文字、窗口标题和坐标。

指标来源上报的字段
几台机器频道下不同的设备 ID设备 ID（随机）、平台（win / mac）
agent 切换MCP 握手时的 clientInfo.name，外加钩子事件客户端名称（claude-code / codex …）、时间戳
屏幕数常驻进程心跳一个整数
拍肩次数DO 收到的事件手势类型、是否跨机器送达
上线前必须同步更新 README 的「数据在你手里」一节，写明收集哪几项、存多久， 并提供 SHOULDER_TAP_TELEMETRY=0 开关。关掉之后，跨机器照常可用，只是不上报统计。
Codex 能不能像 Claude Code 那样挂 Stop / PreToolUse 钩子来触发拍肩，还没核实，动手前要查它当前的文档。 MCP 那条路一定能接上 Codex，所以统计不受影响。

05 — 决定

选了什么，放弃了什么

Cloudflare Durable Objects，而不是 Vercel 加 Redis 轮询

WebSocket 推送延迟在一秒以内；hibernation 下空闲连接几乎不花钱；频道状态、活跃判定和转发都放在一个对象里。

代价：多一个要部署的服务、多一家平台；Vercel 那边的 MCP 保持不变。

后端统一放在 Cloudflare，不引入 Supabase

MCP 本来就是无状态的，搬进 Worker 几乎不用改；DO 自带 SQLite，历史记录直接存在里面，一个平台就够了。

代价：要把 Next.js 的 /mcp 路由改写成 Worker 的写法；现有用户的 MCP 地址要改。

历史记录存密文，不存明文

历史要留下来，又要做到「服务端读不到内容」，唯一的办法就是存加密后的 blob，查看时在本机解密。

代价：服务端没法按内容搜索或统计；token 一旦换掉，旧的历史就解不开了。

本机优先：活跃的就是本机时，钩子直接拍，不绕云端

常驻进程按服务端的广播把「活跃的是不是我」写进 active.json，钩子先看它。最常见的情况（你就在这台上）零网络往返，150 毫秒；中转挂了也不影响单机体验。本机直接拍的那一下由常驻进程经 WebSocket 补记进历史。

代价：文件十分钟内算数，常驻进程刚断线的那几秒可能拍错台（拍在本机而不是你刚切过去的那台）。

服务端负责路由，客户端不自己过滤

不是本机时，DO 只把消息推给活跃的那台，别的机器根本收不到，不会出现两台同时拍、也不会出现谁都没拍。

代价：服务端知道哪个设备 ID 在什么时候活跃。

用 Notion token 当身份，不另做账号

每台机器本来就有这个 token，同一个 token 就等于同一个人，而且零配置。

代价：拿到 token 的人也能往你的频道里发消息，不过 token 泄露本来就是更大的问题。
